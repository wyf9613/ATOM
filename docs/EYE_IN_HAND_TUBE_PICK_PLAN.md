# 末端视觉定位试管与 Gazebo 演示计划

日期：2026-09-25。状态：总体实施提案；腕部相机、四槽 Gazebo 场景、预观察与无环境避障两段接近已完成仿真基线，尚未实现试管抓取或放置。

阶段性记录：已建立“已标定世界系目标位姿 + 底座粗略二维位姿”的预观察假设，完成高度/粗略方位对准、0.40 m 对准位和 0.10 m 垂直接近三段运动；两段接近期间持续发布/记录目标更新，仅在段间采用最新有效观测。RGB、RGB-D 各一例成功运行的精度见 [单例对比](RGB_VS_RGBD_SINGLE_RUN_COMPARISON_20260925.md)；团队另报告 10 次 RGB 测试中 4 次因规划失败终止，逐次记录待归档。后续优先加入预观察可达性检查、取得夹爪控制代码、制作并标定试管架与相机转接件，再开展小范围实机验证。下文的“今日 demo”保留为实施计划与验收条件，不能据此推断各项均已完成。

## 目标与当前起点

在 UF850 腕部安装一台相机，分别试验普通 RGB 相机和单台 RGB-D 深度相机两种互斥配置，得到试管相对机械臂基座的位姿，更新 MoveIt 抓取目标。相机配置是选型对照实验；定位算法另比较“固定工位坐标加视觉残差补偿”和“完全由末端视觉确定目标”两种方式。今天先完成可录屏的 Gazebo 闭环演示。

当前仓库已有 ROS 2 Jazzy / Gazebo Harmonic 下的 UF850 裸臂、TF、MoveIt 规划与模拟轨迹控制；`transfer_demo.py` 使用 `transfer_targets.yaml` 中固定的 `world` 位姿。双层架上的四槽试管架、槽 1 中的透明动态试管、临时 vendor G1 夹爪和两种互斥模拟腕部相机已能运行预观察与两段视觉接近并生成检测报告，详见 [`CAMERA_EXPERIMENT.md`](CAMERA_EXPERIMENT.md)。当前阶段目标为通过 Tag ID 1/2 定位，在同一试管架内执行槽 1 → 槽 2；旧桌面目标架已从场景移除。G1 关节控制已做单条指令检查；夹持试管、碰撞感知取放及 attached object 尚未实现。

## 两种定位方式

| 项目 | 方案 1：固定目标加残差补偿 | 方案 2：直接识别试管 |
| --- | --- | --- |
| 先验 | 已知工位/试管架的名义位姿和槽位到试管抓取位的几何关系 | 只给搜索范围、试管尺寸及抓取规则；每次从图像求试管位姿 |
| 观测 | 每槽旁的唯一 AprilTag ID 索引槽位；普通相机用标签尺寸与内参估计位姿，深度相机模式评估其可用的图像/深度输出并独立估计目标 | 在各相机模式下直接检测试管，利用该相机实际可用的信息估计中心、轴线和可抓取高度；必要时多视角观测 |
| 优点 | 与当前固定目标链路改动小；移动底盘停靠偏差与工位移动可用同一变换修正；容易做对照实验 | 可处理槽位未知、试管位置或姿态变化较大的情况 |
| 主要风险 | 试管必须可靠地位于已标定槽位；标记可见；架位姿不等于单支试管真实位姿 | 透明/反光试管的深度可能无效或落在背景；遮挡、细小目标和抓取轴线使单帧 6D 位姿不稳定 |
| 开发顺序 | **今天的主线** | 后续独立评估；今天最多做图像显示或可观测性摸底 |

两种方式共用同一个抓取目标接口，不能让识别节点直接下发机械臂运动。将观测时间戳、frame、目标 ID、有效性、置信/质量指标和标定版本一起传给任务节点。姿态过期、TF 缺失、标记丢失、深度无效或目标超出工作区时不开始运动。

## 两阶段状态定义

当前流程先拆为预观察阶段和接近阶段。预观察阶段的目标是让腕部相机在不进行大范围水平搜索的情况下看到目标 Tag；接近阶段才根据视觉结果改变末端的水平位置并进入槽位。

### 预观察阶段

预观察阶段从同一个 topic 接收粗略方向和预观察高度：

```text
/atom/pre_observation_target   geometry_msgs/msg/PoseStamped   link_base
pose.position.z                 pre-observation TCP height (m)
pose.orientation yaw            coarse bearing (rad, CCW about link_base +Z)
pose.position.x/y               ignored as input; target node computes 0.35 m along yaw by default
```

当前仿真先用 `theta_true + U(-5°, +5°)` 发布，角度以 `link_base` 的 +Z 轴为旋转轴，正方向为逆时针；高度由理论 Tag 高度和 provisional 相机安装偏移计算。`theta_true` 来自仿真真值，随机项模拟底座定位误差；后续将由底座位姿和试管架位姿计算，不能把该 topic 当作绝对准确的最终目标。目标 Tag ID 由任务上下文指定：夹取为 ID 1，放置为 ID 2；该临时 `PoseStamped` topic 不携带目标 ID。

预观察阶段只做以下动作：

1. 读取粗略方向和已知目标高度；
2. 将末端移动到基座原点沿目标方向 0.35 m 的位置和目标高度；
3. 将夹爪延伸方向调到粗略方向，使相机光轴朝向目标 Tag；
4. 等待姿态和传感器稳定，采集同步 RGB、CameraInfo，以及 RGB-D 模式下的深度；
5. 检测所需 Tag，估计 `T_camera_tag`，通过 TF 变换到基座，并结合 Tag 到槽位的标定偏移生成观测目标；
6. 只有观测有效、时间戳新鲜且质量指标通过，才允许进入接近阶段。

预观察阶段不负责完整避障。目标位姿节点默认把末端放到基座原点沿粗略方向 0.35 m 处；`pre_observation_demo` 已完成该距离的运动和观测，原 0.2 m 目标仍受当前仿真工作空间限制。固定关节观察往返保留为旧基线。

### 接近阶段

本轮接近阶段只到达 Tag 前方的观察/接近位，不执行抓取、放置或下降。现订阅 `/atom/approach_task`（`std_msgs/msg/String`，JSON 字段 `tag_id: 1|2` 与 `action: pick|place`）；未收到外部任务时脚本发布临时 `{ "tag_id": 1, "action": "pick" }`。本轮只用 ID 筛选目标，动作类型仅记录。`/atom/approach/tag_observation`（`std_msgs/msg/String`）发布 JSON，含选定 ID、`link_base` 位姿、相机模式、深度质量、阶段和图像时间戳；同时写入 `tag_observations.jsonl`。这些 JSON 接口是实验接口，正式消息类型后续再定义。第一段使用选定 ID 在预观察结束时的观测中心；Tag1/Tag2 中心连线仅用于估计该共面试管架的稳定水平法线，不把另一 Tag 当目标，也不使用 Gazebo 真值规划。

将 `link_eef` 原点记为 `E`，夹爪延伸方向的单位向量记为 `d`，本阶段的前端参考点明确为 `F = E + 0.20 m · d`。该 0.20 m 是当前任务指定的几何参考距离，不等同于现有模型中尚未实测的 `gripper_tcp`。设目标 Tag 平面中心为 `T`，朝向机器人一侧的单位法线为 `n`。`F` 到平面的有符号垂直距离为 `n · (F − T)`；为避免 Tag 法线正负号翻转，须用相机所在侧和观测朝向检查 `n`。当前 Tag 竖直，接近期间 `E` 的高度、横滚、俯仰固定为预观察结束时的实测值，只允许 `E` 的 `x/y/yaw` 改变。前端点在恒定高度的法线平行射线上运动，其水平坐标满足 `F_xy(s) = T_xy + s n_xy`，其中 `s` 是垂直于 Tag 平面的距离。相机瞄准以**相机光心到 Tag 中心**为准，必须经 `T_eef_camera` 计算，不能用夹爪前端射线代替。

1. **到达对准点**：取预观察结束时选定 Tag 的有效位姿为第一段目标快照，令 `s = 0.40 m`，反算末端目标 `x/y/yaw`。用 MoveIt 从预观察结束的实际关节状态规划并执行；高度与姿态使用路径约束，返回轨迹的相机视线角度由逐点 FK 检查。若受 MoveIt 姿态约束参数化影响而无法得到合格轨迹，使用恒高、恒横滚/俯仰的笛卡尔锚点回退。此段不提供环境避障地图，但保留 MoveIt 的关节限制和自碰撞检查。
2. **第一段视觉更新**：运动期间以可配置频率处理目标 Tag 的 RGB/CameraInfo；RGB-D 模式额外同步深度并检查质量。每次有效观测按图像时间戳使用 TF 转为 `link_base` 位姿，发布到单独的目标观测 topic，并记录 ID、相机模式、时间戳、位姿和质量。初始建议最多处理 5 Hz（当前模拟相机为 10 Hz），实际频率和延迟需记录。更新只供观测和下一段使用，不修改正在执行的第一段轨迹。
3. **垂直接近**：第一段执行完成后读取该段最新、有效且未过期的**同一 ID**观测，使用观测中心及 Tag1/Tag2 连线更新共面机架法线。以对准位的实际状态为起点，令 `s` 从当前值沿这条固定的法线平行射线减到 `0.10 m`，使前端参考点停在距 Tag 平面 0.10 m 处。第二段保留同样的高度、横滚、俯仰验收和相机视线逐点验收，并增加限制 `F` 沿法线射线运动的路径位置约束；如果起点与更新后的射线不在容差内，当前实现停止并报告，不把离线点冒充法线接近。
4. **第二段视觉更新与结果**：执行期间继续发布、记录新观测，但不改变本段已采用的目标快照或已下发轨迹。到位后用实际 TF 计算前端点到**第二段规划所用 Tag 平面**的有符号距离、横向偏差、末端高度与横滚/俯仰变化、相机光轴到 Tag 中心的夹角，并在命令行打印两段规划/执行状态、使用的 Tag ID、观测时间戳和上述误差；随后返回成功或具体失败原因。另记录与最新观测的差异，不能用运动后的新观测偷偷替换验收基准。

实现中先尝试 MoveIt 路径约束规划；当前水平转向时，OMPL 的姿态约束产生超过严格倾斜阈值的路径，因此第一段可回退为 20 个保持世界高度/横滚/俯仰的笛卡尔锚点，由 MoveIt 生成完整轨迹。第二段额外使用前端点法线通道位置约束。执行前对每个轨迹点做 FK 检查：末端高度、倾斜、相机光轴对目标中心的角度和第二段法线偏差；完整路径不满足容差则拒绝执行，执行时再按 TF 抽样检查。当前 `VisibilityConstraint` 默认关闭，因为其遮挡模型在本场景产生无效起点；相机指向用 FK 验收，不能声称由 MoveIt 连续原生约束精确保证。名义场景 RGB/RGB-D 各有一次端到端通过记录；环境避障、运动中重规划、视觉伺服和真实硬件精度仍待验证。

## 坐标与数据链

建议保留模块化描述：`base_link → ... → link_eef → xarm_gripper_base_link → gripper_tcp`。相机以固定关节接在临时 G1 基座下方，光轴与夹爪 `+Z` 指向一致，因此随机械臂末端和夹爪整体姿态同步运动；`camera_mode=rgb|depth` 每次只能生成一个传感器，其中 `depth` 是一台同时输出 RGB 与深度的 RGB-D 设备。移动底盘接入后，机械臂安装变换接到 `base_link`，不要把世界坐标下的工位位置写死到机械臂模型里。两种相机各自的内参、夹爪到相机的固定外参，以及夹爪 TCP 和槽位几何均要独立标定；仿真安装值需标为 provisional。

方案 1 的抓取目标可写为：

```text
T_base_grasp = T_base_camera · T_camera_tag · T_tag_slot · T_slot_grasp
```

其中 `T_base_camera` 来自机械臂 FK 与所选相机安装外参，`T_camera_tag` 来自该相机的实际观测，后两项来自每个 tag ID 对应的槽位几何标定。与名义位姿的差只用于展示残差；实际规划使用观测得到的完整变换链。这样底盘停靠偏移、末端运动以及工位旋转均按同一坐标关系处理。当前接近阶段以 `link_eef` 规划并使用其沿夹爪延伸方向 0.20 m 的前端参考点计算 0.40/0.10 m 平面距离；后续真正抓取目标仍须采用经过测量/标定的夹爪 TCP，不能把这个临时前端点当作抓取 TCP。

方案 2 将 `T_camera_tag · ...` 换成视觉估计的 `T_camera_tube · T_tube_grasp`。不能把 2D 检测框中心或单点深度直接当抓取位姿。对透明试管，深度用于可用性判断和场景观测，目标位姿先结合轮廓、已知尺寸/架约束或多视角估计，并用独立真值验证。

## 今日 Gazebo demo：最小闭环

1. **场景与传感器**：沿用 UF850 仿真；上层四槽试管架每个槽正面放置唯一 ID 的 AprilTag，透明动态试管初始位于槽 1，槽 2 为空。腕部通过启动参数二选一安装模拟普通相机或深度相机，不同时加载。分别桥接各模式实际产生的图像、CameraInfo 和深度图；确认时间戳、光学坐标和 TF 连通。此项的场景/传感器链路已搭建，夹持及放置未完成。
2. **视觉目标**：在预观察阶段，两种模式用各自 RGB 图像和 CameraInfo 运行相同的 AprilTag 检测；目标节点用 Tag ID 1 生成抓取 `PoseStamped`，用 Tag ID 2 生成放置 `PoseStamped`，替换当前固定的 `pick_pose` 和 `place_pose` 输入。RGB-D 模式额外评估深度对 Tag 距离估计和目标有效性的增益。接近阶段只消费通过质量检查的视觉目标，不在预观察阶段直接执行抓取动作。保留固定目标作为对照，分别打印两个槽位名义目标与观测目标的平移差（m）及旋转差（rad）。
3. **扰动对照**：固定随机种子，至少演示两组工位摆放：名义位置和一个明确记录的平移/偏航扰动。相机重新观测后，目标位置应随之变化；固定目标不会变化。对照试验中保持机器人起始关节位形相同。
4. **规划执行**：先通过粗略方向完成预观察；接近阶段按选定 Tag 依次到前端距平面 0.40 m 的对准位及 0.10 m 的终点，在两段各自规划时冻结一份目标观测。MoveIt 规划并用 TF 检查前端点距离及沿途高度/姿态/视线误差。此轮只验证无环境障碍接近；场景几何进入 PlanningScene 后再验证避障，抓取和放置另行实现。
5. **夹取边界**：若当日组合夹爪控制、抓取反馈和 attached object 均通过，继续闭合、抬升、搬运、释放。否则视频清楚标注为“视觉定位 + 规划接近”演示，不将裸臂到位或 `simulate_grasp_success` 解释为成功夹取。可用 Gazebo/ROS 画面叠加显示检测、TF 目标、规划轨迹与执行结果。

当日完成条件：录到 Gazebo 中相机看到标记/试管、ROS 2 输出有效观测目标、工位扰动造成目标更新、MoveIt 执行更新后的安全接近轨迹；保存两组目标位姿、实际末端位姿、误差、规划/执行结果和视频。若相机渲染或 AprilTag 接入受阻，最低降级演示是由仿真传感器提供带时间戳的架位姿并走同一 TF/规划接口；录屏必须明确标注该位姿不是图像检测结果。

建议按当天剩余时间分配：先用约 1–2 小时打通场景、图像与 TF，再用约 1–2 小时完成标签定位和扰动对照，然后用约 1 小时接入规划并保存证据，最后留约 30 分钟录制 60–90 秒视频。若相机链路超过前两个时间窗仍不稳定，优先完成可如实标注的 TF/规划闭环，不在当天并行攻克真实透明试管识别和夹爪动力学。视频镜头按“初始固定目标 → 工位扰动 → 相机检测与更新目标 → MoveIt 规划/执行 → 误差与演示边界”排列。

## 实施次序与验证

| 阶段 | 产物 | 通过条件 |
| --- | --- | --- |
| A. 相机和场景 | 模块化相机 Xacro、试管架/试管 SDF、桥接配置、launch | Gazebo 和 RViz 可见；RGB、深度、CameraInfo、TF 时间与 frame 一致 |
| B. 视觉与目标 | AprilTag 配置、架到槽位变换、预观察 topic、接近任务 topic、目标有效性检查 | 预观察给出选定 ID 的观测；接近两段运行期间持续发布并记录同一 ID 的更新；目标过期、丢标记或 TF 缺失时禁止开始下一段 |
| C. 规划演示 | 目标接入两段接近 MoveIt 链路、约束误差报告和录屏脚本 | 前端点先到 0.40 m，再沿更新后的法线射线到 0.10 m；末端高度/横滚/俯仰保持，视线在角度容差内；规划失败或部分路径不会执行，环境避障另验 |
| D. 真正夹取 | 组合夹爪 URDF/SRDF/控制、TCP、接触与 attached object | 试管从槽 1 被夹持、随夹爪抬升并释放到槽 2，且碰撞检查均有可重复证据 |
| E. 方案 2 | 直接试管检测、RGB/深度融合或多视角估计 | 在位置/姿态扰动及遮挡下，与独立真值比较位置、角度、失效率和延迟 |

记录每次试验的场景配置/随机种子、样本数、单位、相机及 TF 时间戳、目标真值与估计值、最终 TCP 误差、失败原因。今天的仿真结果不代表真实透明试管的深度质量或实机抓取精度。实体集成前需确认相机型号/安装空间与线缆、手眼标定、真实 TCP、底盘停靠误差及是否允许在架上放标记。
