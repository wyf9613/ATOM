# 末端视觉定位试管与 Gazebo 演示计划

日期：2026-09-24。状态：总体实施提案；腕部相机和四槽 Gazebo 实验环境已搭建，视觉目标接入规划及抓取尚未完成。

## 目标与当前起点

在 UF850 腕部安装一台相机，分别试验普通 RGB 相机和单台 RGB-D 深度相机两种互斥配置，得到试管相对机械臂基座的位姿，更新 MoveIt 抓取目标。相机配置是选型对照实验；定位算法另比较“固定工位坐标加视觉残差补偿”和“完全由末端视觉确定目标”两种方式。今天先完成可录屏的 Gazebo 闭环演示。

当前仓库已有 ROS 2 Jazzy / Gazebo Harmonic 下的 UF850 裸臂、TF、MoveIt 规划与模拟轨迹控制；`transfer_demo.py` 使用 `transfer_targets.yaml` 中固定的 `world` 位姿。双层架上的四槽源架、桌面目标架、透明动态试管、临时 vendor G1 夹爪和两种互斥模拟腕部相机已能运行观察轨迹并生成正面标签检测报告，详见 [`CAMERA_EXPERIMENT.md`](CAMERA_EXPERIMENT.md)。G1 关节控制已做单条指令检查；视觉目标接入 MoveIt、夹持试管、碰撞感知取放及 attached object 尚未实现。今日演示不能以这些能力已存在为前提。

## 两种定位方式

| 项目 | 方案 1：固定目标加残差补偿 | 方案 2：直接识别试管 |
| --- | --- | --- |
| 先验 | 已知工位/试管架的名义位姿和槽位到试管抓取位的几何关系 | 只给搜索范围、试管尺寸及抓取规则；每次从图像求试管位姿 |
| 观测 | 每槽旁的唯一 AprilTag ID 索引槽位；普通相机用标签尺寸与内参估计位姿，深度相机模式评估其可用的图像/深度输出并独立估计目标 | 在各相机模式下直接检测试管，利用该相机实际可用的信息估计中心、轴线和可抓取高度；必要时多视角观测 |
| 优点 | 与当前固定目标链路改动小；移动底盘停靠偏差与工位移动可用同一变换修正；容易做对照实验 | 可处理槽位未知、试管位置或姿态变化较大的情况 |
| 主要风险 | 试管必须可靠地位于已标定槽位；标记可见；架位姿不等于单支试管真实位姿 | 透明/反光试管的深度可能无效或落在背景；遮挡、细小目标和抓取轴线使单帧 6D 位姿不稳定 |
| 开发顺序 | **今天的主线** | 后续独立评估；今天最多做图像显示或可观测性摸底 |

两种方式共用同一个抓取目标接口，不能让识别节点直接下发机械臂运动。将观测时间戳、frame、目标 ID、有效性、置信/质量指标和标定版本一起传给任务节点。姿态过期、TF 缺失、标记丢失、深度无效或目标超出工作区时不开始运动。

## 坐标与数据链

建议保留模块化描述：`base_link → ... → link_eef → gripper_tcp`，相机通过可选的安装描述接在腕部；`camera_mode=rgb|depth` 每次只能生成一个传感器，其中 `depth` 是一台同时输出 RGB 与深度的 RGB-D 设备。移动底盘接入后，机械臂安装变换接到 `base_link`，不要把世界坐标下的工位位置写死到机械臂模型里。两种相机各自的内参、末端手眼外参，以及夹爪 TCP 和槽位几何均要独立标定；仿真值需标为 provisional。

方案 1 的抓取目标可写为：

```text
T_base_grasp = T_base_camera · T_camera_tag · T_tag_slot · T_slot_grasp
```

其中 `T_base_camera` 来自机械臂 FK 与所选相机安装外参，`T_camera_tag` 来自该相机的实际观测，后两项来自每个 tag ID 对应的槽位几何标定。与名义位姿的差只用于展示残差；实际规划使用观测得到的完整变换链。这样底盘停靠偏移、末端运动以及工位旋转均按同一坐标关系处理。规划目标应是 `gripper_tcp`；在组合模型就绪前，可暂用 `link_eef` 和明确的临时偏移，仅作为裸臂接近演示。

方案 2 将 `T_camera_tag · ...` 换成视觉估计的 `T_camera_tube · T_tube_grasp`。不能把 2D 检测框中心或单点深度直接当抓取位姿。对透明试管，深度用于可用性判断和场景观测，目标位姿先结合轮廓、已知尺寸/架约束或多视角估计，并用独立真值验证。

## 今日 Gazebo demo：最小闭环

1. **场景与传感器**：沿用 UF850 仿真；上层源架每个槽正面放置唯一 ID 的 AprilTag，桌面放目标架，源槽放透明动态试管。腕部通过启动参数二选一安装模拟普通相机或深度相机，不同时加载。分别桥接各模式实际产生的图像、CameraInfo 和深度图；确认时间戳、光学坐标和 TF 连通。此项的场景/传感器链路已搭建，夹持及放置未完成。
2. **视觉目标**：两种模式用各自 RGB 图像和 CameraInfo 运行相同的 AprilTag 检测；目标节点按 tag ID 找槽位并生成 `PoseStamped`，覆盖当前固定 `pick_pose` 输入。RGB-D 模式额外评估深度对目标存在性及三维几何定位是否有增益。保留固定目标作为对照，打印名义与观测目标的平移差（m）及旋转差（rad）。
3. **扰动对照**：固定随机种子，至少演示两组工位摆放：名义位置和一个明确记录的平移/偏航扰动。相机重新观测后，目标位置应随之变化；固定目标不会变化。对照试验中保持机器人起始关节位形相同。
4. **规划执行**：先到安全观察位，获取有效观测，再生成抓取上方位和接近位；MoveIt 规划、执行并用 TF 检查 `link_eef` 到目标的误差。场景有实物模型时将桌面、架和试管的简化碰撞体同步加入 PlanningScene，接近接触区的允许碰撞须单独配置和验证。
5. **夹取边界**：若当日组合夹爪控制、抓取反馈和 attached object 均通过，继续闭合、抬升、搬运、释放。否则视频清楚标注为“视觉定位 + 规划接近”演示，不将裸臂到位或 `simulate_grasp_success` 解释为成功夹取。可用 Gazebo/ROS 画面叠加显示检测、TF 目标、规划轨迹与执行结果。

当日完成条件：录到 Gazebo 中相机看到标记/试管、ROS 2 输出有效观测目标、工位扰动造成目标更新、MoveIt 执行更新后的安全接近轨迹；保存两组目标位姿、实际末端位姿、误差、规划/执行结果和视频。若相机渲染或 AprilTag 接入受阻，最低降级演示是由仿真传感器提供带时间戳的架位姿并走同一 TF/规划接口；录屏必须明确标注该位姿不是图像检测结果。

建议按当天剩余时间分配：先用约 1–2 小时打通场景、图像与 TF，再用约 1–2 小时完成标签定位和扰动对照，然后用约 1 小时接入规划并保存证据，最后留约 30 分钟录制 60–90 秒视频。若相机链路超过前两个时间窗仍不稳定，优先完成可如实标注的 TF/规划闭环，不在当天并行攻克真实透明试管识别和夹爪动力学。视频镜头按“初始固定目标 → 工位扰动 → 相机检测与更新目标 → MoveIt 规划/执行 → 误差与演示边界”排列。

## 实施次序与验证

| 阶段 | 产物 | 通过条件 |
| --- | --- | --- |
| A. 相机和场景 | 模块化相机 Xacro、试管架/试管 SDF、桥接配置、launch | Gazebo 和 RViz 可见；RGB、深度、CameraInfo、TF 时间与 frame 一致 |
| B. 视觉与目标 | AprilTag 配置、架到槽位变换、目标有效性检查 | 两个工位位姿下观测目标均能与 Gazebo 真值比较；过期/丢标记禁止执行 |
| C. 规划演示 | 目标接入现有 MoveIt 链路、场景碰撞体、日志和录屏脚本 | 同一起点完成名义/扰动两次接近；固定与视觉目标差异可见，规划失败不会执行 |
| D. 真正夹取 | 组合夹爪 URDF/SRDF/控制、TCP、接触与 attached object | 夹爪闭合反馈、试管随夹爪抬升、释放和碰撞检查均有可重复证据 |
| E. 方案 2 | 直接试管检测、RGB/深度融合或多视角估计 | 在位置/姿态扰动及遮挡下，与独立真值比较位置、角度、失效率和延迟 |

记录每次试验的场景配置/随机种子、样本数、单位、相机及 TF 时间戳、目标真值与估计值、最终 TCP 误差、失败原因。今天的仿真结果不代表真实透明试管的深度质量或实机抓取精度。实体集成前需确认相机型号/安装空间与线缆、手眼标定、真实 TCP、底盘停靠误差及是否允许在架上放标记。
